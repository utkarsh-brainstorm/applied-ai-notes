1. Recap — Where We Left Off

In the previous lecture, the setting for Gradient Descent was established: we are given a scalar-valued function f that consumes a vector and produces a single number—for instance, a loss function, where the input is a data point of dimension n (fed to a neural network) and the output is compared against a label (discrete for classification, continuous for regression). Once this loss is defined, the task becomes finding the parameters that minimize it.

To do this, we defined the function and its gradient vector, which stacks all the partial derivatives with respect to every variable. The variables x1​,…,xn​ are general placeholders—in practice, these are the weights of a neural network or the learnable parameters of any ML model.

We saw that Gradient Descent minimizes a function by:

  1. Initializing a solution x(0) and a step size (learning rate) α.
  2. Repeatedly moving from the current solution to the next one in the direction of the negative gradient, scaled by α.

For a minimization problem, the step is subtracted (move against the gradient). For a maximization problem, the step is added (move along the gradient)—this is called Gradient Ascent.

We also observed that the rate of convergence depends heavily on α: too small, and convergence is painfully slow; too large, and the solution can diverge to an undefined value entirely. The safe default is to start with a small learning rate—it won't diverge, but it will take longer.

Note for Review: The single biggest lever in Gradient Descent is the learning rate α. Every variant discussed in this lecture (SGD, Momentum, AdaGrad, RMSProp, Adam) is fundamentally about finding smarter ways to set or adapt α—either to converge faster or to stop it from blowing up.

Today's lecture builds on this by:

  • Generalizing Gradient Descent to the multivariable case with a formal proof.
  • Addressing the computational cost of computing gradients over huge datasets.
  • Addressing the problem of different gradient magnitudes along different directions.

2. The Gradient Vector and Directional Derivative

Let f:Rn→R be a scalar function. The gradient of f(x1​,x2​,…,xn​) is defined as

∇f=⎣⎡​∂x1​∂f​∂x2​∂f​⋮∂xn​∂f​​⎦⎤​.

Geometrically, for a level curve f(x1​,x2​)=c, the gradient ∇f is a vector that is perpendicular to the level curve at every point, pointing toward increasing values of f.

The directional derivative of f along a unit direction vector v, at a point x, tells us the instantaneous rate of change of f if we move along v:

Dv​f(x)=v⊤∇f(x)=cosθ∥∇f(x)∥,

where θ is the angle between v and ∇f(x).

Key Fact

The directional derivative is maximized when v points in exactly the same direction as ∇f(x) (that is, θ=0∘):

∥v∥=1max​v⊤∇f(x)=∥∇f(x)∥,

which occurs when

v=∥∇f(x)∥∇f(x)​.

This single fact is the entire justification for gradient-based optimization: the gradient points in the direction of steepest ascent, so moving opposite to it is, locally, the fastest way to decrease f.

brucks

The Gradient Descent Algorithm

Let ∇f(x) be the gradient of f at point x.

Algorithm: Gradient Descent

Input: Initial point x(0), learning rate α

  1. Initialize x(0) and choose a step size α.

  2. Set t←0.

  3. While not converged do

  4. Update the parameters:

    x(t+1)=x(t)−α∇f(x(t))

  5. Increment the iteration counter:

    t←t+1

  6. End while

Every subsequent variant discussed in this lecture (SGD, Momentum, AdaGrad, RMSProp, Adam) is a modification of line 4 of this algorithm — either changing what gradient is used, or changing how the step size α behaves.

4. Why Does Gradient Descent Actually Work? (Taylor Series Proof)

Deriving the Gradient Descent Update Rule (Taylor Series)

So far the update rule was stated without proof. Here is where it comes from, generalized to n dimensions using a first-order Taylor series expansion.

Let f:Rn→R, and consider a point x perturbed by a very small vector ϵ (every component of ϵ is small). By the definition of the multivariate Taylor series,

f(x+ϵ)=f(x)+1!ϵ⊤∇f​+2!1​ϵ⊤∇2fϵ+⋯

Here ∇2f is the Hessian (the matrix of second-order partial derivatives), and there are infinitely many further higher-order terms—we only need the first-order term for this argument.

Goal

We want to choose ϵ such that

f(x+ϵ)<f(x),

i.e., we want to move to a point with a smaller function value.

Choice of ϵ

Pick

ϵ=−η∇f,η>0,

where η is the learning rate, always chosen to be positive.

Substituting this ϵ into the Taylor expansion

Dropping the second-order and higher-order terms (since ϵ is very small),

f(x−η∇f)=f(x)−η1!∇f⊤∇f​.

Since 1!=1,

f(x−η∇f)=f(x)−η∇f⊤∇f.

Using the identity

∇f⊤∇f=∥∇f∥22​,

we obtain

f(x−η∇f)=f(x)−η∥∇f∥22​.

Why does this decrease the function?

Notice that

∇f⊤∇f=∥∇f∥22​

is exactly the squared 2-norm of the gradient, which is always non-negative because it is a sum of squares.

Since η>0, the quantity

η∥∇f∥22​

is also non-negative and is being subtracted from f(x).

Therefore,

f(x−η∇f)<f(x),

whenever

∇f=0.

brucks

Interpretation

If we move from the current point x to the new point

x−η∇f,

the function value decreases (as long as ∇f=0). This means the new point is a better solution than the current one under the first-order approximation, so repeating this update continues moving toward a minimum.

The Gradient Descent Mapping

The parameter update is

x⟶x−η∇f(x).

The corresponding function values evolve as

f(x)⟶f(x−η∇f(x)),

with

f(x−η∇f(x))<f(x).

This is exactly the iterative update rule of Gradient Descent—now derived rather than assumed.

📝 Note for Review: This proof only guarantees a decrease for a sufficiently small \eta — because we dropped the second-order (Hessian) term, which is only negligible when \epsilon is small. This is precisely why an overly large learning rate can cause divergence: the dropped higher-order terms are no longer negligible, and the "guaranteed decrease" argument breaks down.

5. Worked Example 1 — Single Variable, f(x) = x^2

Example: Effect of Learning Rate in Gradient Descent

Consider f(x)=x2, and we want to find the point of minima using Gradient Descent starting at x0​=10.

Analytically we know the minimum is at x∗=0, since

f′(x)=2x=0⇒x=0.

The update rule for this one-dimensional case is simply

x(t+1)=x(t)−α⋅2x(t).

Three Different Learning Rates

Learning Rate (α) Behavior
α=0.20 Converges smoothly and quickly to x=0 in roughly 10 iterations.
α=0.05 Converges, but far more slowly—after the same 10 iterations, the solution is still noticeably far from 0.
α=1.10 Diverges. Starting from f(10)=100, the solution overshoots the minimum on every step, and the function value explodes—reaching roughly 4000 within about 10 iterations, oscillating wildly with further iterations.

brucks

Visualization of Different Learning Rates

The α=1.10 series follows the exact update

x(t+1)=x(t)−1.10⋅2x(t)=x(t)(1−2.2)=−1.2x(t).

So the magnitude grows by a factor of 1.2 every iteration while the sign flips each step—a textbook divergence pattern.

Takeaway

Correctly choosing the learning rate is the single most important practical decision in Gradient Descent:

  • Small α: stable but slow convergence.
  • Well-chosen α: fast convergence.
  • Large α: overshooting and divergence.

The same idea applies to maximization problems—here, maximizing the likelihood of a binary, linearly-separable classification problem. The predictor is parameterized by θ via the sigmoid function, and its output is treated as a probability:

hθ​(xi​)=1+e−θ⊤xi​1​

  2. Set t←0.

    $$ \theta_j^{(t+1)} \leftarrow \theta_j^{(t)}

  2.   Set t←t+1.

Notice the plus sign in the update rule. Since we are maximizing the likelihood (gradient ascent), we move along the gradient instead of against it.

The gradient here was derived previously. The important structural detail—which motivates everything in the next section—is that updating a single parameter θj​ requires a summation over all m training examples.

8. The Computational Bottleneck — Why We Need Something Better

Look closely at the update equation above.

To update just one parameter θj​, you must compute a summation over all m training data points:

i=1∑m​(yi​−hθ​(xi​))xij​.

For a large dataset—say, hundreds of thousands or millions of training points—this becomes computationally expensive, and it must be repeated:

  • for every parameter in the model, and
  • at every iteration of gradient ascent or gradient descent.

As datasets become larger and more complex, models usually require more parameters to capture the underlying patterns. This increases the computational cost even further.

Example: Linear Regression Has the Same Problem

Consider linear regression, where the loss function is

L(θ)=i=1∑n​ei2​=i=1∑n​(xi⊤​θ−yi​)2.

Here,

  • yi​ is the ground-truth label.
  • xi⊤​θ is the model's prediction.

Dividing by n does not change the location of the minimum, so we often write the loss in the more general form

L(θ)=n1​i=1∑n​fi​(xi​,θ).

Taking the gradient with respect to θ gives

∇θ​L(θ)=n1​i=1∑n​∇fi​.

The Universal Computational Pattern

The same summation over the entire dataset appears in almost every machine learning objective function.

Whether it is:

  • Linear Regression
  • Logistic Regression
  • Neural Networks
  • Support Vector Machines
  • Deep Learning models

the gradient is typically computed as an aggregate over all training examples.

This is the fundamental computational bottleneck of Batch Gradient Descent, and it motivates faster optimization methods such as Stochastic Gradient Descent (SGD) and Mini-Batch Gradient Descent.

📝 Note for Review: This is the exact motivation for Stochastic Gradient Descent — instead of asking "how do I make gradient descent more accurate," the question becomes "how do I make each step of gradient descent computationally cheap enough to actually run on large data?"

9. Stochastic Gradient Descent (SGD)

Given the loss form

f(x)=n1​i=1∑n​fi​(x),

the exact Gradient Descent update is

x(t+1)=x(t)−αn1​i=1∑n​∇x​fi​(x),

which is computationally expensive for large n.

The SGD Idea

Instead of summing over the entire dataset, randomly pick a single data point i and use only its gradient as an (unbiased) estimate of the true gradient:

x(t+1)=x(t)−α∇x​fi​(x).

This drastically simplifies each update—no summation over the whole dataset is needed.

It can be shown (proof omitted here, available in standard references) that this estimate is sufficient for convergence, although the optimization trajectory will show fluctuations rather than a perfectly smooth path.

In Practice: Mini-Batch SGD

Rather than using a single data point, a small random batch (mini-batch) is used to approximate the gradient. This is called Mini-Batch SGD.

It retains the computational benefit while also making efficient use of GPU/CPU parallelism (since batches vectorize well), and the mini-batch estimate is less noisy than using a single point.

Batch Gradient Descent vs SGD vs Mini-Batch SGD

Behavior

Using the same function and starting point as the earlier example, Mini-Batch SGD (or single-point SGD) follows a path similar to full-batch Gradient Descent.

However, as it approaches the minimum, it begins to fluctuate around the optimal solution instead of settling smoothly.

This happens because a single data point (or a small batch) provides only a noisy approximation of the true gradient, and this noise does not disappear completely near the optimum.

Two Ways to Reduce the Fluctuation

  1. Increase the batch size.

    A larger mini-batch reduces the variance (noise) of the gradient estimate, producing a smoother optimization path.

  2. Use a dynamically decaying learning rate.

    As training progresses, gradually reduce the step size so that noisy updates become smaller near the optimum.

10. The Dynamic Learning Rate Trick

Instead of keeping α fixed for every iteration, make it a function of the iteration number t:

α(t)=α0​e−λt,

where

  • α0​ is the initial learning rate.
  • λ is the decay rate.
  • t is the iteration number.

Why This Works

  • Early training (small t): The learning rate is close to α0​, so updates are large and optimization progresses quickly.
  • Later training (large t): The exponential factor shrinks toward zero, making updates progressively smaller.

As the learning rate decreases, the fluctuations caused by noisy SGD gradients become much smaller, allowing the optimizer to settle near the optimum.

Exponential Learning Rate Decay

α(t)=α0​e−λt​

This is called exponential learning rate decay.

Note for Review: This decaying-learning-rate idea reappears (in different clothing) inside AdaGrad, RMSProp, and Adam. All of them effectively reduce the effective learning rate during training, although they use gradient statistics (rather than just the iteration number) to determine how much the step size should shrink.---

11. The Dimensional Scaling Problem

When One Learning Rate Isn't Enough

So far, every example used a function where gradients in different directions were roughly comparable in scale. But consider

f(x1​,x2​)=0.1x12​+2x22​.

Gradient

∇f(x1​,x2​)=[0.2x1​4x2​​].

At the point (10,10),

∇f=(0.2×10,4×10)=(2,40).

Multiplying by a learning rate α:

  • Step in the x1​ direction:

    2α

  • Step in the x2​ direction:

    40α

This is a 20× difference in step size for the same learning rate.

If

α=0.1,

then

  • x1​ step = 0.2
  • x2​ step = 4

This means one direction has a very gently sloping surface (small gradient, slow convergence), while another direction has a very steeply sloping surface (large gradient, risk of overshoot or divergence). A single, shared learning rate cannot be ideal for both simultaneously.

brucks

Experiment 1 — α=0.4

Starting from (−5,−2):

  • The x2​ direction (steep) converges quickly, reaching close to x2​=0 in about 5–7 iterations, because its gradient is large and α=0.4 is still small enough to avoid divergence.
  • The x1​ direction (gentle) is painfully slow. After the same 7 iterations, x1​ has only moved from −5 to around −2.5, because the gradient along x1​ is small and becomes even smaller as the point approaches the optimum.

Given enough iterations, this still converges—but very slowly along the x1​ direction.

Experiment 2 — α=0.6

Now the x1​ direction moves nicely from −5 toward 0.

However, the x2​ direction diverges.

Because the gradient in the steep direction is much larger, multiplying it by the larger learning rate causes the update to overshoot the minimum by an increasing amount at every iteration.

By around iteration 15, x2​ has exploded from −2 to roughly 1000, oscillating and diverging further with additional iterations.

The Core Dilemma

You cannot pick a single learning rate that is simultaneously safe for a steep direction and fast for a gentle direction.

This is precisely the problem that motivates Momentum and adaptive learning-rate methods such as AdaGrad, RMSProp, and Adam.

12. Momentum — "Don't Lose the Momentum"

Looking back at the plain update rule, notice that to go from one point to the next, we only used the gradient computed at the current point. The gradients from earlier steps were discarded.

The Momentum Idea

Instead of using only the most recent gradient, aggregate gradients from previous steps as well.

To update from the current point, use information from gradients computed at previous iterations, with different weights controlled by a parameter β.

In other words, don't lose the momentum you've already built up.

Update Equations

The momentum update is

vt​=βvt−1​+gt,t−1​,

where

gt,t−1​=∇x​(∣Bt​∣1​i∈Bt​∑​fi​(xt−1​)).

The parameter update becomes

xt​=xt−1​−αt​vt​.

Here,

  • gt,t−1​ is the gradient computed on the current mini-batch (or full batch).
  • vt​ is the running weighted aggregate, often called the velocity.
  • β controls how much past gradients are remembered.

brucks

Why Momentum Fixes Both Problems

Gentle Direction (e.g. x1​)

The gradient is small but consistently points in the same direction at every iteration.

Adding together many small, aligned gradients produces a larger velocity, increasing the effective step size and accelerating convergence along the gentle direction.

Steep / Oscillating Direction (e.g. x2​)

The gradient repeatedly flips sign as the optimization overshoots the minimum.

For example,

  • positive,
  • negative,
  • positive,
  • negative.

When these gradients are accumulated, positive and negative contributions partially cancel each other, reducing the effective step size and damping oscillations.

The Big Picture

Gradient aggregation helps in both failure modes simultaneously:

  • Amplifies small, consistent gradients in shallow directions.
  • Cancels large, oscillating gradients in steep directions.

As a result, momentum produces a smoother optimization trajectory and typically converges faster than plain Gradient Descent.

With momentum (for example, β=0.25), the earlier slow-convergence/divergence problem is greatly reduced, and the trajectory converges smoothly along both axes.

The gradient used in gt,t−1​ may come from:

  • Full Batch Gradient Descent,
  • Stochastic Gradient Descent (SGD), or
  • Mini-Batch SGD.

Momentum works with all of these optimization frameworks.

Note for Review: Don't set β too aggressively. Since momentum accumulates gradients over many iterations, an overly large β can initially create excessively large updates in some directions. Although momentum is designed to stabilize optimization, β itself is an important hyperparameter that must be tuned.

13. AdaGrad — Adaptive Gradient

Momentum aggregates gradients to build velocity, but keeps a single, shared learning rate across all dimensions. AdaGrad instead gives each parameter its own adaptive learning rate, based on how large that parameter's historical gradients have been—directly targeting the problem from Section 11.

Here the notation switches to a machine learning framing:

  • xt​ is the t-th training data point.
  • ω represents the model's weights (parameters).

Update Equations

First compute the gradient:

gt​=∇ω​ℓ(yt​,f(xt​,ω)).

Accumulate the squared gradients:

st​=st−1​+gt2​.

Update the parameters:

ωt​=ωt−1​−st​+ϵ​α​gt​.

What Each Term Means

  • gt​ is the gradient vector (one component per parameter or feature).
  • st​ is a vector that accumulates the element-wise square of the gradient over time.
  • gt2​ means square each component individually (not a dot product).
  • Squaring, square roots, and division are all element-wise operations.
  • ϵ is a small safety constant that prevents division by zero when a parameter has received zero gradient updates.

Why AdaGrad Helps

Unlike ordinary Gradient Descent, where the same learning rate α multiplies every parameter update, AdaGrad gives each parameter its own effective learning rate:

st​+ϵ​α​.

This quantity is a vector, so every parameter gets a different step size.

  • Large historical gradients: st​ becomes large, so the effective learning rate shrinks.
  • Small or infrequent gradients: st​ stays small, so the effective learning rate remains relatively large.

This is especially useful for machine learning datasets containing:

  • Frequent features: receive many large gradient updates.
  • Rare features: receive sparse or small gradient updates.

AdaGrad automatically slows learning for frequent features while continuing to learn quickly for rare ones.

Note for Review — The Flaw in AdaGrad: st​ is a cumulative running sum of squared gradients. It only grows over time—it never decreases.

Therefore,

st​+ϵ​α​

monotonically shrinks toward zero, even if the model has not converged.

In practice, AdaGrad often becomes so conservative after many iterations that training nearly stops.

This exact weakness motivates RMSProp.

brucks

14. RMSProp

RMSProp (Root Mean Square Propagation) fixes AdaGrad's "ever-growing denominator" problem.

Instead of storing a cumulative sum, it stores an exponentially weighted moving average of squared gradients, controlled by a decay parameter γ.

Update Equations

Compute the gradient:

gt​=∇ω​ℓ(yt​,f(xt​,ω)).

Update the running average:

st​=γst−1​+(1−γ)gt2​.

Update the parameters:

ωt​=ωt−1​−st​+ϵ​α​gt​.

Comparing AdaGrad and RMSProp

AdaGrad uses

st​=st−1​+gt2​,

so every squared gradient is remembered forever.

RMSProp uses

st​=γst−1​+(1−γ)gt2​,

which gives exponentially less weight to older gradients.

The decay parameter γ controls the trade-off:

  • Larger γ → longer memory.
  • Smaller γ → recent gradients matter more.

Why RMSProp Works Better

Because old gradient information gradually decays,

  • st​ remains bounded.
  • st​ can even decrease if recent gradients become smaller.
  • The effective learning rate no longer collapses permanently toward zero.

As a result, RMSProp usually continues learning much longer than AdaGrad.

15. Adam — Adaptive Moment Estimation

Adam combines Momentum with RMSProp.

It keeps track of:

  1. A moving average of gradients (first moment).
  2. A moving average of squared gradients (second moment).

Update Equations

Step 1 — Compute the Gradient

gt​=∇ω​ℓ(yt​,f(xt​,ω)).

Step 2 — First Moment (Momentum)

vt​=β1​vt−1​+(1−β1​)gt​.

Step 3 — Second Moment (RMSProp)

st​=β2​st−1​+(1−β2​)gt2​.

Step 4 — Bias Correction

v^t​=1−β1t​vt​​,s^t​=1−β2t​st​​.

Step 5 — Parameter Update

ωt​=ωt−1​−s^t​​+ϵαv^t​​.

How the Pieces Fit Together

First Moment (vt​)

The first moment is the momentum-style moving average of the raw gradient.

Because gradients keep their signs,

  • positive gradients,
  • negative gradients,

can partially cancel each other in oscillating directions.

This produces a smoother, more stable update direction.

brucks

Second Moment (st​)

The second moment is the RMSProp-style moving average of squared gradients.

Since squared gradients are always non-negative,

  • they never cancel,
  • they track the typical gradient magnitude for each parameter.

This determines the adaptive learning rate for every parameter individually.

Bias Correction

Early in training, both vt​ and st​ start near zero.

Without correction, the moving averages are biased toward zero during the first few iterations.

Adam corrects this by dividing by

1−β1t​and1−β2t​,

so early updates are not artificially suppressed.

Final Interpretation

The final Adam update combines both mechanisms:

  • Momentum (v^t​): determines the update direction and smooths oscillations.
  • Adaptive scaling (s^t​): adjusts the learning rate independently for every parameter.

In short,

Adam=Momentum+RMSProp​

or, conceptually:

Adam = Momentum's "which direction and how big a step" + RMSProp's "how much to trust and scale that step for each parameter."

brucks

16. Summary — Comparing All the Variants

Algorithm Core Idea Fixes Key Formula Component
Gradient Descent Move against the full-dataset gradient. Baseline optimality guarantee (via Taylor series). x_{t+1} = x_t - \alpha \nabla f(x_t)
SGD (mini-batch) Approximate the gradient using 1 point / a small batch. Computational cost of summing over the whole dataset. x_{t+1} = x_t - \alpha \nabla f_i(x_t)
Dynamic LR Decay \alpha over iterations. Fluctuation near the optimum caused by noisy SGD gradients. \alpha(t) = \alpha_0 e^{-\lambda t}
Momentum Aggregate gradients across past steps. Slow convergence (gentle direction) and oscillation/divergence (steep direction), simultaneously. v_t = \beta v_{t-1} + g_t
AdaGrad Give each parameter its own learning rate, shrinking with its historical squared-gradient sum. A single shared \alpha being wrong for different-scale directions. s_t = s_{t-1} + g_t^2
RMSProp Same as AdaGrad, but use an exponential moving average instead of an ever-growing sum. AdaGrad's learning rate collapsing to zero permanently. s_t = \gamma s_{t-1} + (1-\gamma)g_t^2
Adam Combine Momentum's signed gradient aggregate with RMSProp's adaptive scaling, plus bias correction. Needing both directionally-smart and magnitude-aware updates at once. \omega_t = \omega_{t-1} - \dfrac{\alpha \hat v_t}{\sqrt{\hat s_t}+\epsilon}

1. Where We Left Off: From Optimization Theory to Learning Algorithms

Until this point in the course, the focus has been squarely on the machinery of optimization — gradients, constrained optimization, and the algorithms used to solve them. Today marks a turning point: this machinery is finally put to work on an actual machine learning technique. The first learning algorithm to benefit from this optimization toolkit is the Support Vector Machine (SVM).

SVM is fundamentally a binary classifier, although with the right modifications it can be extended to handle multi-class classification as well. For this lecture, the discussion is restricted to the case where the two classes are linearly separable — meaning a straight line (or, in higher dimensions, a flat hyperplane) can perfectly divide the two classes.

Before SVM itself can be defined, however, a purely geometric question needs to be answered: given a hyperplane and a data point, how far is that point from the hyperplane? This quantity — the margin — turns out to be the single most important concept in the entire derivation.

brucks

2. The Geometric Margin: How Far Is a Point From a Line?

Consider a hyperplane

H={x:θ⊤x+b=0}

A line (or hyperplane, in general) can be parameterized in many ways, but here it is described by two things:

  • θ — the normal vector, perpendicular to the hyperplane.
  • b — related to the distance of the hyperplane from the origin.

Now take an arbitrary data point x that does not lie on the hyperplane, and let xp​ be the point on the hyperplane that is closest to x (i.e., the foot of the perpendicular from x). The vector d joining xp​ to x represents exactly the distance we want to compute.

Deriving the distance step by step.

By definition, the vector d points in the same direction as the normal vector θ (since d is perpendicular to the hyperplane, and θ is also perpendicular to it by construction). It may, however, have a different magnitude. So we can write:

x−xp​=αθ

for some unknown scalar α. Since xp​ lies on the hyperplane, it must satisfy the hyperplane equation:

θ⊤xp​+b=0

Substituting xp​=x−αθ into this equation:

θ⊤(x−αθ)+b=0

Expanding and solving for α:

α=θ⊤θθ⊤x+b​

Now, the distance itself is just the magnitude of d:

∥d∥2​=∥x−xp​∥2​=∥αθ∥2​

Substituting the value of α found above, and using the fact that θ⊤θ=∥θ∥22​ (so one factor of ∥θ∥2​ cancels):

∥d∥2​=∥θ∥2​∣θ⊤x+b∣​

This is the geometric margin of a point x with respect to a hyperplane (θ,b) — a clean, closed-form expression for "how far is this point from my classifier."

Note for Review: Students often forget why the denominator is ∥θ∥2​ and not ∥θ∥22​. It comes purely from ∥αθ∥2​=∣α∣∥θ∥2​, and α itself already carries one power of ∥θ∥2−2​ in its denominator — one power cancels against the ∥θ∥2​ picked up from taking the norm, leaving exactly one power of ∥θ∥2​ in the final denominator.

brucks

3. Scale Invariance: The Hyperplane's Best-Kept Secret

Here's a subtle but extremely important property. Suppose the parameters (θ,b) representing a hyperplane are scaled by some positive constant γ, giving a new pair (γθ,γb). Does the hyperplane change?

γθ⊤x+γb=0⟹θ⊤x+b=0

Since γ=0, it can simply be divided out — the equation reduces back to the original hyperplane. The scaled parameters represent exactly the same hyperplane.

Now the natural follow-up: does the margin change under this scaling?

∥γθ∥2​∣γθ⊤x+γb∣​=γ∥θ∥2​γ∣θ⊤x+b∣​=∥θ∥2​∣θ⊤x+b∣​

Both the numerator and denominator pick up the same factor of γ (since γ>0), which cancels out completely.

Conclusion: Both the hyperplane and its geometric margin are invariant to positive scaling of (θ,b). This is a trivial fact to prove, but it will soon become the single most useful trick in solving the SVM optimization problem — because it means there is a whole family of (θ,b) pairs that all represent the same classifier, and among that family, one can always pick the most convenient representative.

4. Setting Up the Support Vector Machine

With the geometric toolkit ready, the Support Vector Machine itself can now be defined.

Consider a labeled dataset:

D={(x1​,y1​),(x2​,y2​),…,(xn​,yn​)}

where each data point xi​ has a corresponding binary label yi​. Here comes SVM's one quirky convention: instead of using {0,1} as in logistic regression, SVM labels the two classes as

yi​∈{−1,+1}

There is nothing deep about this choice — it is simply more convenient algebraically, as will become clear very soon when the two "positive side" and "negative side" conditions get merged into a single inequality.

The goal is to find a linear boundary — a hyperplane — that separates the two classes.

Since the two classes above are linearly separable, a classifier can indeed be found — but, as the next section shows, which classifier to pick is far from obvious.

brucks

5. Why Maximize the Margin? A Tale of Infinite Classifiers

Looking at the scatter plot above, it's tempting to think the job is done once any line correctly separates the green and red points. But here's the catch: there are infinitely many such lines. Any small rotation or shift of a valid separating line, as long as it doesn't cross into the other class's territory, is still a perfectly valid classifier by the "correctly separates the data" criterion alone.

So which one should be chosen? Consider two extreme choices:

  • A classifier that hugs the red class very closely.
  • A classifier that hugs the green class very closely.

In both cases, a small amount of measurement noise could push a borderline point across the classifier, causing a misclassification. A point sitting very close to the boundary is fragile — the slightest perturbation flips its predicted class.

The fix is intuitive: choose the classifier that stays as far away as possible from both classes simultaneously — i.e., the one with the maximum margin. This gives the classifier the largest possible "buffer zone" to absorb noise before any point gets misclassified.

This reframes the classification problem: instead of *"find a linear boundary that separates the two classes,"* the goal becomes *"find a linear boundary that separates the two classes and maximizes the margin between them."*

Since the margin of an individual point is just its distance from the classifier, and every dataset has many points at varying distances, the natural next question is: the margin of which point? Points that are already far from the boundary are of no real concern — they will not flip sides easily. The points that matter are the ones closest to the boundary on each side. Hence, the objective becomes: maximize the minimum margin across the entire dataset.

6. Turning Intuition Into Constraints

Before margins can be maximized, the "correctly separates the two classes" requirement needs to be written as a precise mathematical constraint.

Consider the classifier x⊤θ+b=0, with normal vector θ and distance-from-origin parameter b. Take a data point xi​ lying on the positive side of this hyperplane (the side θ points toward). Since xi​ is not on the line itself:

xi⊤​θ+b=0,and specificallyxi⊤​θ+b>0

All points on this side are, by convention, labeled yi​=+1.

Now take a point xj​ on the negative side:

xj⊤​θ+b<0,labeled yj​=−1

Here is where the {−1,+1} labeling convention pays off. Multiply the positive-side inequality by yi​=+1: the inequality direction is unchanged, and it stays positive. Multiply the negative-side inequality by yj​=−1: the inequality flips, turning a negative quantity into a positive one:

yj​(xj⊤​θ+b)>0

Both cases — positive-side and negative-side — now collapse into the exact same single condition:

yi​(θ⊤xi​+b)>0,for all i=1,…,n

This one inequality, applied to every training point, guarantees that all points are on the correct side of the classifier. (For now, the possibility of a point sitting exactly on the boundary — margin equal to zero — is set aside, which is why a strict ≥0 boundary rather than >0 will be used going forward.)

brucks

7. The (Messy) Maximum-Margin Optimization Problem

Combining everything so far: the goal is to find (θ,b) that (a) correctly separates the two classes, and (b) maximizes the minimum margin over all data points. This is written as:

γ(θ,b)=xi​∈Dmin​∥θ∥2​∣θ⊤xi​+b∣​θ,bmax​γ(θ,b)such thatyi​(θ⊤xi​+b)≥0

This is unlike anything solved earlier in the optimization module. Previously, every problem was a simple maximization or minimization of a cost function, possibly with equality constraints. This problem, on the other hand, is:

  1. A genuine constrained optimization problem (an inequality constraint must hold for every data point), and
  2. Nested — it's a max of a min, since the margin itself is defined as a minimization over data points.

Solving a max-min problem directly is unpleasant. The next section shows how the scale-invariance property from Section 3 elegantly collapses this nested structure into a much simpler single-level problem.

8. The Scaling Trick: Cleaning Up the Sandwich

Step 1 — Pull the denominator out of the minimization.

Look carefully at the margin expression:

γ(θ,b)=∥θ∥2​1​xi​∈Dmin​∣θ⊤xi​+b∣

The inner minimization runs over data points xi​, while ∥θ∥2​ does not depend on xi​ at all — it can be factored completely outside the minimization. This gives:

θ,bmax​∥θ∥2​1​xi​∈Dmin​∣θ⊤xi​+b∣s.t.yi​(θ⊤xi​+b)≥0,i∈{1,…,n}

Step 2 — Use scale invariance to fix the inner minimum to exactly 1.

Recall from Section 3: scaling (θ,b) by any positive constant changes neither the hyperplane nor the margin. This means that for any candidate hyperplane (θ,b) for which mini​∣θ⊤xi​+b∣=c (some positive number), a rescaled version can always be constructed:

θ^=cθ​,b^=cb​

so that:

xi​min​∣θ^⊤xi​+b^∣=1

Since this rescaling changes neither the hyperplane nor the margin, there is no loss of generality in restricting attention only to hyperplanes for which the closest point has ∣θ⊤xi​+b∣=1. This constraint can simply be added to the optimization problem, and because it fixes the minimum to exactly 1, the entire inner minimization term drops out of the objective (it's just the constant 1 now):

θ,bmax​∥θ∥2​1​s.t.yi​(θ⊤xi​+b)≥0,i∈{1,…,n}imin​∣θ⊤xi​+b∣=1,i∈{1,…,n}

brucks

Step 3 — Merge the two constraints into one.

Because yi​(θ⊤xi​+b)≥0 for every point, the same absolute-value trick from Section 6 applies again: ∣θ⊤xi​+b∣=yi​(θ⊤xi​+b). So the condition mini​∣θ⊤xi​+b∣=1 becomes:

imin​yi​(θ⊤xi​+b)=1⟹∀i,yi​(θ⊤xi​+b)≥1

Note something important here: this new constraint, yi​(θ⊤xi​+b)≥1, is strictly stronger than the earlier one, yi​(θ⊤xi​+b)≥0. Any (θ,b) satisfying the former automatically satisfies the latter — so the original ≥0 constraint becomes redundant and can be dropped entirely.

Step 4 — Flip maximization into minimization.

Maximizing ∥θ∥2​1​ is mathematically equivalent to minimizing ∥θ∥2​, which is in turn equivalent to minimizing θ⊤θ (squaring is a monotonic transformation for non-negative quantities, and it conveniently removes the square root hidden inside the norm, making the problem smooth and quadratic).

This finally yields the clean, canonical Support Vector Machine optimization problem:

θ,bmin​θ⊤θsuch thatyi​(θ⊤xi​+b)≥1,i∈{1,…,n}

Note for Review: This scaling trick is the crux of the entire derivation and a very common exam question. The key idea to remember: maximizing margin subject to a max-min structure is intractable directly, but scale-invariance lets you "fix" the hardest constraint to a constant (1) without losing generality, collapsing the problem into an ordinary single-level constrained quadratic minimization.

9. Support Vectors: The VIPs of the Dataset

For the optimal parameters (θ,b) found by solving the problem above, the two lines

x⊤θ+b=1andx⊤θ+b=−1

are not arbitrary — they pass exactly through the nearest data points of the two classes. These are precisely the data points for which the constraint is tight, i.e.,

yi​(θ⊤xi​+b)=1

Such points are called the support vectors — they are the points that are literally "supporting" the maximum-margin classification region. Every other data point, sitting further away, plays no active role in determining the exact position of the optimal hyperplane once the support vectors are known.

The two circled points above sit exactly on the dashed margin lines — these are the support vectors for this particular dataset. Notice how removing any of the other (non-circled) points would not change the optimal hyperplane at all, since they never appear as tight constraints.

brucks

10. When Classes Refuse to Separate: Slack Variables

Everything so far assumed the two classes are linearly separable. But real datasets are rarely so accommodating. Consider a case where a handful of points genuinely violate the clean separation — for instance, one negative-class point that ends up mixed in among the positive class, and vice versa. In such a scenario, no (θ,b) can satisfy yi​(θ⊤xi​+b)≥1 for every single data point.

In the plot above, one green point (3.4, 4.5) has drifted onto the red side, and one red point (3.0, 5.6) has drifted onto the green side. If the previously-derived orange hyperplane is used, these two points end up on the wrong side of the classifier.

Should the whole idea of SVM be abandoned here? Not at all — in practice, only a small number of data points typically violate the separability condition, while the vast majority still sit comfortably on their correct side. Rather than demanding perfection from every point, the constraint can simply be relaxed for the problematic ones.

Introducing the slack variable. For each data point i, a non-negative slack variable ηi​≥0 is introduced, which measures how much that particular point is allowed to violate the margin constraint:

θ,b,ηmin​θ⊤θ+Ci∑​ηi​such thatyi​(θ⊤xi​+b)≥1−ηi​ηi​≥0

Here, ηi​=0 for any point that already satisfies the original hard constraint, while ηi​>0 allows that specific point to fall inside the margin (or even on the wrong side of the hyperplane) by an amount proportional to ηi​. The constant C>0 controls how harshly these violations are penalized in the objective — allowing some slack is fine, but allowing unlimited slack defeats the purpose, so the sum of slacks is added back into the cost function as a penalty.

Combining the two constraints into one expression. Both inequalities above can be merged into a single unconstrained-looking penalty term. Whenever yi​(θ⊤xi​+b)≥1, no slack is needed at all (ηi​=0 is optimal); whenever it falls short, the required slack is exactly ηi​=1−yi​(θ⊤xi​+b). This is precisely captured by a hinge function:

θ,b,ηmin​θ⊤θ+Ci∑​max{0,1−yi​(θ⊤xi​+b)}

This single expression elegantly folds the margin-maximization objective, the classification constraint, and the slack penalty into one unconstrained cost function — the deeper justification for why this combination is valid will be explored further in the live sessions.

Note for Review: The constant C is essentially a regularization knob. A very large C forces the model to punish margin violations heavily, pushing it toward the hard-margin behavior (small margin, few/no violations, but sensitive to noise). A very small C tolerates more violations in exchange for a wider, more robust margin. This trade-off is exactly analogous to bias–variance trade-offs seen elsewhere in ML.

brucks

11. Rewriting Everything as a Single Matrix Problem

Having derived the (hard-margin) optimization problem

θ,bmin​θ⊤θs.t.yi​(θ⊤xi​+b)≥1,i=1,…,n

the next task is to actually solve it. Since the cost function θ⊤θ only involves θ while the minimization is over both θ and b, it helps to first bring b explicitly into the objective. This can be done for free by adding a 0×b⊤b term:

θ⊤θ+0⋅b⊤b

which changes nothing numerically but makes the notation symmetric in θ and b.

Unpacking the constraints one at a time. Writing out the first constraint (i=1) fully:

y1​(x1⊤​θ+b)≥1⟹y1​x1⊤​θ+y1​b≥1

(note that y1​ is a scalar, so no transpose is needed on it.) Similarly for i=2:

y2​x2⊤​θ+y2​b≥1

and so on, up to the n-th point:

yn​xn⊤​θ+yn​b≥1

Spotting the pattern. In every one of these n constraints, the unknown quantities are always θ and b — identical across every row. What changes from row to row are the known quantities: yi​xi⊤​ and yi​, both of which are fully determined by the training data. This means all n constraints can be stacked into a single matrix inequality.

Define the stacked parameter vector:

ω=[θb​]

and the data matrix A, where row i packs together the known quantities for constraint i:

A=⎣⎡​y1​x1⊤​y2​x2⊤​⋮yn​xn⊤​​y1​y2​⋮yn​​⎦⎤​

You can verify that multiplying row i of A with the column vector ω reproduces exactly yi​xi⊤​θ+yi​b — the left-hand side of constraint i. So all n constraints collapse into one matrix inequality:

Aω≥1

where 1 is a vector of all ones, of size n×1 (bold-face 1 to emphasize it is a vector, not the scalar one).

Rewriting the objective in terms of ω. The augmented cost function θ⊤θ+0⋅b⊤b can itself be written as a single quadratic form in ω:

θ⊤θ+b⊤0b=[θ⊤​b⊤​][I0​00​][θb​]=ω⊤Bω,B=[I0​00​]

Here I is the identity matrix matching the dimension of θ, so that B simply "switches off" the b-component while leaving the θ-component untouched — exactly reproducing θ⊤θ.

The final matrix-form optimization problem:

ωmin​ω⊤Bωsuch thatAω≥1

This is now recognizable as a very standard class of optimization problem: the objective is quadratic in ω, and the constraint is linear. This makes it a linearly-constrained quadratic optimization problem — a Quadratic Program (QP) with inequality constraints. This is a well-studied class of problems, and solving it (for inequality-constrained problems in general) will be the subject of upcoming lectures.

brucks

12. A Warm-Up: Solving an Equality-Constrained Problem

Before tackling the inequality-constrained QP above, it's useful to build intuition with a much simpler equality-constrained problem — the SVM's inequality version will build on the exact same technique, extended appropriately.

The toy problem. Suppose the goal is:

ωmin​ω⊤Aωsuch thatω⊤ω=1

(assume A is symmetric). In words: minimize this quadratic form, but only among vectors ω of unit norm.

Why not just minimize freely? If the constraint were ignored, the trivial minimizer would be ω=0, since 0⊤A0=0 is the smallest possible value a quadratic form of this type can take (assuming A positive semi-definite, or simply the global minimum in this toy setting). But the zero vector clearly fails ω⊤ω=1 — so unconstrained minimization is not automatically compatible with the constraint. The constraint has to be actively enforced.

The penalty (Lagrange multiplier) approach. A penalty term is introduced that equals zero whenever the constraint is satisfied, and grows whenever ω deviates from it:

L(ω,λ)=ω⊤Aω−λ(ω⊤ω−1)

Taking the gradient with respect to ω and setting it to zero (using A symmetric, so ∇ω​(ω⊤Aω)=2Aω):

2Aω−2λω=0⟹Aω=λω

This is nothing but the standard eigenvalue–eigenvector equation: ω must be an eigenvector of A, and λ the corresponding eigenvalue.

Connecting back to the objective. Multiplying both sides of Aω=λω on the left by ω⊤:

ω⊤Aω=λω⊤ω=λ(since ω⊤ω=1)

So the value of the objective function at any eigenvector solution is simply the corresponding eigenvalue λ. Since the goal is to minimize ω⊤Aω, the optimal ω must be the eigenvector of A corresponding to its smallest eigenvalue.

Note for Review: This technique — introducing a penalty term proportional to how much a constraint is violated, then differentiating — is the essence of the Lagrange multiplier method. Here it was applied to an equality constraint, producing an elegant eigenvalue problem. The SVM's actual constraints are inequalities, not equalities, so this exact eigen-trick does not directly transfer; a more general framework (Lagrangian duality with KKT conditions) is needed, which builds on this same core idea and will be covered in upcoming lectures.
