Recap and Roadmap

This course is structured around four questions that recur throughout every topic we study. Knowing them by heart helps you place any new concept into context — whenever we introduce something new, it is almost always in service of answering one of these four questions. This lecture is devoted to the first question in detail, and then transitions into the second.

The first question — what are the attributes or features of the data — is primarily about terminology. It doesn't carry deep conceptual weight on its own, but it establishes the vocabulary that every later discussion depends on. If a dataset is described as "a data object with attribute so-and-so," you need to know precisely what that means.

Anatomy of a Dataset: From D to Observations

Every discussion starts with a dataset (or database), denoted D. This is the all-encompassing unit — everything the analysis will ever touch lives inside it. From here, we peel back layers of abstraction one at a time.

Dataset D comprises data objects. A data object is simply an entity — a single entry recorded in the database. A database can (and usually does) contain many data objects.

Consider a Sales Database. Its data objects could include:

  • Customer ID — identifying information for the person who made the purchase
  • Store item — the product being sold
  • Sales figure — the record of the sale itself

The exact list of data objects depends entirely on context, requirements, and the kind of analysis being performed — there is no fixed universal list.

A Hospital Database gives a second example. Here, each patient can be thought of as a data object, and a patient may be described through several such objects: patient history, current medication, treatment records, and so on.

Going one level deeper: a data object is itself characterized by attributes. An attribute is a data field — a feature or characteristic of a data object. The value that an attribute takes for a specific data object is called an observation.

Putting it together for a Customer data object: the attributes might be Customer-ID, Name, and Address. The specific values those attributes hold for one particular customer (e.g., ID = 4722, Name = "XYZ") are the observations.

Note for Review: Keep the hierarchy straight — Database → Data Object → Attribute → Observation. Almost every terminology confusion in this course traces back to mixing up which level of this hierarchy a term belongs to.

The Many Aliases of an Attribute

The word "attribute" is not universal — the same underlying idea shows up under different names depending on which field you're standing in. This is purely a matter of disciplinary convention, but recognizing it prevents unnecessary confusion when switching between textbooks or communities.

Term Field Where It's the Popular Choice
Attribute Data Mining
Feature (or feature vector) Machine Learning
Dimension Data Warehousing
Variable Statistics

All four terms describe exactly the same thing: a characteristic of a data object. When you encounter any of them going forward, translate it mentally into "a describable property of the thing being recorded."

Attribute Vectors: The Heterogeneous Cousin of ML Feature Vectors

If we collect all the attributes of one data object into a single ordered list, we get an attribute vector (equivalently, a feature vector — the term you likely already know from ML).

For the Customer data object, this vector might look like:

Customer={Customer-ID4722​​, NameXYZ​​, Addressabc​​}

This is where data mining departs from the "clean" ML feature vector you may be used to. In machine learning, feature vectors are typically purely numeric — every entry is a number you can meaningfully interpret as big or small. Here, however, the vector mixes an ID, a name (text), and an address (text). This is called a heterogeneous vector: an attribute vector whose entries come from entirely different attribute types and cannot be meaningfully compared to one another (you cannot compare a name to an ID).

Note for Review: "Heterogeneous" is the key word examiners like to test. It doesn't mean the vector is disorganized — it means the entries are not mutually comparable because they represent fundamentally different kinds of attributes.

Types of Attributes

Not all attributes behave the same way mathematically. Knowing an attribute's type tells you exactly what operations (comparison, averaging, subtraction) are actually meaningful to perform on it. There are four types worth knowing well.

1. Nominal (Categorical) Attributes

Values are drawn from a fixed, predefined set of category names — nothing more. Examples:

  • Occupation = {doctor, driver, teacher, …}
  • Gender = {M, F, other}
  • Customer ID = 4722 (a system-generated label, not a "real" number)

By definition, nominal attributes carry no quantitative meaning. Statements like "4722 > 4615" or "the average customer ID is 3749.74" are technically computable but meaningless — customer IDs were never numbers in the arithmetic sense to begin with.

Despite lacking quantitative meaning, nominal attributes are still extremely valuable for pattern discovery — e.g., noticing that customers with occupation "doctor" tend to buy a certain category of car.

2. Binary Attributes

A special case of nominal attributes restricted to exactly two categories:

  • True / False
  • 1 / 0
  • Positive / Negative (e.g., a malaria test result)
  • Male / Female

Binary attributes are still nominal in spirit — "1 > 0" or "1 + 0 = 1" carries no real meaning here — but their two-valued structure makes them common and worth naming separately (e.g., married/unmarried fields in a database).

3. Ordinal Attributes

Unlike nominal attributes, ordinal attributes do carry numerical significance — you can meaningfully compare them — but the values are still restricted to a discrete, predefined set (no values are allowed "in between").

Example — Quality of Service rating:

Score Meaning
0 Very dissatisfied
1 Somewhat dissatisfied
2 Neutral
3 Satisfied
4 Very satisfied

Notice that 1.5 or 3.7945 are not permitted — only the five discrete levels exist. Yet the ranking is meaningful: a rating of 3 genuinely indicates more satisfaction than a rating of 0.

brucks

Example — Letter Grades:

Grade Grade Point
A 10
A- 9
B 8
B- 7
C 6

A grade of 7.5 is never awarded — only the discrete points on this scale are valid. Because the scale is numerically meaningful, it can be averaged — this is exactly what a CGPA is: the mean of several ordinal grade points (e.g., a CGPA of 6.79 vs. 7.54 for two different students).

Restricting grades to discrete points (instead of allowing continuous values like 9.7945 vs. 9.7897) is a deliberate design choice: it reduces unnecessary variance in comparisons. If arbitrary decimal precision were allowed, instructors would end up making distinctions between students that are not really meaningful — the discreteness forces a clear threshold between "this is an A" and "this is an A-."

4. Continuous Attributes

Any numeric value is permitted — 6.7943, 4, 9, or anything in between. Continuous attributes have full arithmetic meaning, but their physical interpretation can be less "clean" than an ordinal attribute's discrete, well-defined categories.

Summary Comparison

Type Quantitative meaning? Discrete or continuous? Example
Nominal / Categorical No Discrete (labels) Occupation, Gender, Customer ID

How to Summarize and Understand Data Better

Real-world datasets are large — a sales database might have thousands of customers and objects running into lakhs or crores of transactions. Manually inspecting every row is infeasible, and usually unnecessary: what you actually want, as a first instinct, is a summary. A good summary can immediately tell you whether last month's sales deviated meaningfully from the trend, sparing you a deep dive unless something looks off.

Before diving into specific summary measures, we need two foundational terms: population and sample.

Data, in this context, means a set of measurements — numbers collected during an experiment or investigation (e.g., blood pressure, heart rate, sales, profit). This is distinct from nominal attributes gathered through a survey or interview (like a customer's name); measurement implies you are recording a genuine numeric quantity.

Parameter vs. Statistic: The Unknown Truth vs. Your Best Guess

  • Parameter: a set of meaningful measurements corresponding to the entire collection of units — i.e., the population.
  • Statistic: a set of measurements collected on a randomly selected subset of units from that collection — i.e., the sample.

Worked example: Suppose the question is *"what is the average blood pressure of 25-year-old males?"* Implicit in this question is a reference to the entire population of 25-year-old males in the world. Measuring blood pressure for every single one of them and averaging the results gives you the parameter.

In practice, measuring an entire population is essentially never possible. Instead, you take a sample — say, 35 randomly chosen individuals — measure their blood pressure, and average those values. That average is the statistic.

Conventionally, the parameter is written as p, and the corresponding sample estimate is written with a "hat," p^​. The critical relationship to internalize:

p=p^​

In practice, p is always unknown — you can never measure the entire population — while p^​ is known, because it is computed directly from the sample you actually collected. The entire discipline of statistical inference exists to reason about the unknown parameter p using the known statistic p^​.

This same idea underlies generalization in machine learning: you train a model on a sample (training set) and hope it performs well on the broader population it will eventually encounter (unseen test data).

Questions like *"what percentage of school-going kids play computer games for more than one hour?"* or *"how many mobile phones currently in use are less than one year old?"* are implicitly population-level questions — no category or filter is specified. Since the full population can't be measured, the honest answer always comes from a sample, followed by an inference back to the population.

Note for Review: Whenever you report a summary statistic, ask yourself: am I describing my sample accurately, and is that description going to be generalized (rightly or wrongly) to the population? This single habit prevents most misleading data summaries.

Quantifying Central Tendency: Mean, Median, Mode

"Quantifying" a parameter or statistic usually means reducing a dataset to a single representative number — mean, median, mode, variance, correlation coefficient, max/min, and so on. These are the basic characteristics of any population or sample, and (mode aside) each one gives a unique description of the dataset.

The Mean — Strengths and Weaknesses

The (arithmetic) mean is by far the most widely used summary statistic. Why it is so dominant is left as an open question worth exploring on your own — but its trade-offs are well documented:

Weaknesses:

  • Sensitive to outliers / skewed data — a few extreme values can dominate the result.
  • Same mean, different distributions — two datasets can share an identical mean while having completely different shapes. The chart below shows two distributions that both have μ=0.296, despite looking nothing alike.
  • Not always interpretable / may not exist in the data. For instance, filling a missing value with the mean of its neighbors (e.g., inserting 3.5 between a 3 and a 4) produces a value that was never actually observed. Similarly, a statement like "there are 50.21 computers per sq. km in a city" is mathematically valid but physically strange.

Strengths:

  • Easy to compute and uses every data value (unlike median or mode, which ignore most of the dataset).
  • Self-correcting as the number of random samples increases.

Open question from the lecture: why is the mean so overwhelmingly popular despite these documented weaknesses? This is left as a genuine research question — try to work out the reasoning yourself before looking it up.

The Median

The median is the central value of the data once arranged in numerical order.

  • Not affected by outliers — a small number of extreme values cannot drag it around the way they can the mean.
  • More useful for skewed data, precisely because it ignores the magnitude of extreme values.

Despite these robustness advantages, the median is less popular than the mean in practice. This is posed as a genuine open question worth exploring: robustness alone doesn't guarantee popularity — what does the median lose that makes analysts reach for the mean instead?

Histogram skewness is directly relevant here: some distributions are symmetric (little to no skew), some are right-skewed (small values dominate in count), some are left-skewed (large values dominate in count), and some are roughly uniform (all bins have similar counts). Whenever your data is skewed, the median is generally the more representative "typical value."

The Mode

The mode is the value (or category) with the highest frequency.

  • Not necessarily unique — a dataset can have multiple modes, or none at all. Note carefully: *"no mode" does not imply the mode is zero* — it simply means no single value dominates.
  • Ignores a lot of information — it only looks at frequency, discarding everything else about the distribution.
  • Especially useful for nominal or qualitative data, where mean and median are not even mathematically valid (you cannot average "doctor" and "driver").

Why Having All Three Isn't Always Enough

Consider two datasets:

  • Set A: 99, 99, 100, 100, 100, 100, 100, 101, 101
  • Set B: 1, 1, 99, 100, 100, 100, 101, 199, 199

Both sets share the exact same mean, median, and mode: 100. Yet they are visibly very different datasets — Set B has extreme values pulled far away on both ends, while Set A is tightly clustered.

This is the central lesson: mean, median, and mode can all agree while the underlying data is completely different. A single summary number is never the whole story — this is exactly why we also need measures of spread, discussed next.

Two natural follow-up questions worth sitting with:

  • When summarizing employee salaries in an organization, which of mean, median, or mode is more suitable — and why?
  • Given two companies' share returns over the last five years, A (%) = {1.8, 1.9, 2.0, 2.1, 2.3} and B (%) = {1.0, 1.1, 1.0, 0.9, 1.3}, which would you invest in, and why? (Hint: mean and median alone won't fully answer this — you'll need spread too.)

Quantifying Spread: Variance and Standard Deviation

A single "typical value" is never enough — you also need to know how spread out the data is around that value. Consider a second version of the share-return example: A (%) = {1.8, 1.9, 2.0, 2.1, 3.6} and B (%) = {1.0, 1.5, 2.0, 3.0, 3.9}. These now differ noticeably in spread even if their central tendency looks similar — which is exactly what variance is designed to capture.

Variance is the mean squared deviation from the population mean:

σ2=N∑i=1N​(xi​−μ)2​

Standard deviation is simply the positive square root of the variance: σ=σ2​.

Two questions worth pondering on your own: which of variance and standard deviation is more popular in practice, and do they really represent the same underlying idea, or are there meaningful differences in how each is used?

Note for Review: Mean, median, mode, variance, and standard deviation are measures you've likely used since school — but popularity is not the same as suitability. Always ask which measure is appropriate for the specific question you're answering, not just which one is most familiar.

When Both Parameter and Statistic Are Known

Normally, the population parameter is unknown, which is precisely why we rely on a sample statistic. But in the rare case where both p and p^​ are known, you gain something valuable: the ability to validate or evaluate your sampling strategy. If p=3.4 but your sample gave p^​=3.1, that deviation is a signal — perhaps the sampling procedure was flawed, or some subgroup was under-represented.

Other Robust Summary Measures

Beyond mean/median/mode and variance/standard deviation, a few additional measures are worth having in your toolkit — especially when robustness to outliers matters.

Range and Dynamic Range

Range=max−min

Range is simple and useful for quick comparisons, but it only ever looks at the two most extreme values in the entire dataset.

A logarithmic variant, the dynamic range, is often more informative:

Dynamic Range=log10​(minmax​)

This measure is widely used in digital photography, audio, and signal processing. In photography, a scene's dynamic range tells you how much contrast (brightness variation) it contains — a higher dynamic range means the scene contains both much brighter and much darker points together, rather than being relatively uniform.

Example — real-world luminance range:

Scene Luminance (cd/m²)
Moonless sky 3×10−5
Full moon 6×103
Sun 2×109

The luminance of real-world scenes spans roughly 14 orders of magnitude, from moonless sky to direct sunlight — which is exactly why a logarithmic scale is necessary to make such numbers manageable, and why plain "range" would be a poor way to compare such extreme spreads.

Open question from the lecture: how robust are range and dynamic range as summary measures, really? Dynamic range is generally considered the more robust of the two — but think through why, and what specific weaknesses of plain "range" it fixes.

Percentiles and Quartiles

For n numerically ordered values (interpolating when there is an even number of observations):

Q1​=4n+1​,Q2​=2n+1​,Q3​=43(n+1)​

where each formula gives the position (rank) in the ordered data at which that quartile lies. Note that:

median=P50​=Q2​

— the median is simply the 50th percentile, which is also the second quartile.

brucks

Inter-Quartile Range (IQR)

IQR=Q3​−Q1​

The IQR is a more robust alternative to the plain range, because it deliberately ignores the most extreme 25% of values on each end — exactly the values that make the plain range so sensitive to outliers.

Try it yourself: the battery life (in hours) of 12 sample units is:

2, 5, 6, 6, 7, 8, 8, 8, 9, 9, 10, 15

The range here is easy: max−min=15−2=13. Now order the data (it already is ordered), locate Q1​ and Q3​ using the formulas above, and compute the IQR. Compare the two numbers — the gap between them is exactly the kind of robustness difference this section has been building toward.

Note for Review: Range only "sees" two data points, no matter how large your dataset is. IQR "sees" the middle 50% of your entire dataset. When you suspect outliers are present, always prefer IQR over range — the same instinct that makes you prefer median over mean in skewed data.

  2. A startup has 40 employees, and the CEO's salary is roughly 20× the typical employee's salary. Which single summary statistic — mean, median, or mode — would you present to investors to describe "typical" pay at the company, and which would you present in a union negotiation arguing that wages are too low? Justify both choices using what you now know about sensitivity to outliers.

  3. Two rooftop sensors log a city's daily temperature for a year.   4. A hospital wants to know what fraction of all diabetic patients nationwide would respond well to a new drug, and tests it on 50 volunteer patients.
