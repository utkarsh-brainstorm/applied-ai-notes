Recap: Linear Regression and the Closed-Form Solution

Before diving into iterative optimization, it's worth briefly revisiting the linear regression setup from the previous session, since gradient descent will later be applied to a problem where this convenient closed-form trick is no longer available.

Consider a training set:

S={(x1​,y1​),…,(xn​,yn​)}

For the i-th data point, the predicted label is a linear combination of its features:

y^​i​=a1​xi1​+a2​xi2​+⋯+an​xin​

Stacking all predictions and ground-truth labels into vectors:

y^​=⎣⎡​y^​1​⋮y^​n​​⎦⎤​,y=⎣⎡​y1​⋮yn​​⎦⎤​,a=⎣⎡​a1​⋮an​​⎦⎤​

The learning goal is to find the coefficient vector a that minimizes the squared distance between predictions and ground truth:

a1​,…,an​min​∥y^​−y∥22​=amin​∥Aa−y∥22​

Here each prediction can be written compactly as y^​i​=a⊤xi​, and the matrix A stacks every data point as a row:

A=⎣⎡​x1⊤​⋮xn⊤​​⎦⎤​

So the objective function becomes:

f(a)=∥Aa−y∥22​

Taking the gradient with respect to a and setting it to zero:

∇f=2A⊤Aa−2A⊤y=0

Solving this gives the closed-form least-squares solution:

a∗=(A⊤A)−1A⊤y

This works beautifully for linear regression because the objective is convex with a single global minimum, which allows us to directly solve for the optimum algebraically. Logistic regression, as we will see later in this lecture, is not so cooperative — it has no closed-form solution, which is exactly why we need gradient descent.

Why We Need Iterative Optimization

In practice, many functions we want to minimize are far messier than the convex quadratic bowl of linear regression. They may have multiple local minima and highly complex expressions, making a closed-form solution to the global optimum impossible to derive.

So the natural question becomes: given a randomly initialized guess x(0) (which is generally not equal to the optimal solution x∗), how do we iteratively nudge this guess closer to the true optimum?

Picture a 1D function with a dip somewhere in the middle. At a starting point x(0), there are only two directions to move: left or right.

  • Moving right (call this x0R​) increases the function value.
  • Moving left (call this x0L​) decreases the function value.

This isn't a coincidence — it comes down to the sign of the slope:

  • If the slope at the current point is positive, moving in the direction of increasing x increases f(x).
  • If the slope is negative, moving in the direction of increasing x decreases f(x).

So, to minimize a function, you should always take a step in the direction opposite to the slope — that is, the negative gradient direction. This single observation is the seed of the entire gradient descent algorithm.

Note for Review: This "always go against the slope" intuition is exactly why the algorithm is called gradient descent*. If you flip the sign and go *with the slope, you get *gradient ascent*, used for maximization problems (like the log-likelihood maximization we'll see in logistic regression later).

The Taylor Series Justification

Why does moving against the gradient actually guarantee a decrease in function value? We can prove this rigorously using a first-order Taylor series expansion.

For a small perturbation ϵ around a point x:

f(x+ϵ)=f(x)+1!f′(x)​ϵ+2!f′′(x)​ϵ2+⋯

Since ϵ is chosen to be very small, all higher-order terms (quadratic, cubic, ...) become negligible, leaving the first-order approximation:

f(x+ϵ)≈f(x)+ϵf′(x)

We now want to find an ϵ such that:

f(x+ϵ)<f(x)

Choose ϵ to point in the negative gradient direction, scaled by a step size η>0 (also called the learning rate):

ϵ=−ηf′(x)

Substituting this back in:

f(x+ϵ)=f(x)−η(f′(x))2

Since η>0 and (f′(x))2≥0, the term η(f′(x))2 is always non-negative. Therefore:

f(x−ηf′(x))<f(x)

This confirms mathematically that stepping in the negative gradient direction is guaranteed to decrease the function value (for a sufficiently small step size).

The Gradient Descent Update Rule

From the Taylor series result, we get the fundamental iterative update rule:

x⟶x−ηf′(x)

Unrolling this over multiple iterations, starting from an initial guess x(0):

x(1)=x(0)−ηf′(x(0))x(2)=x(1)−ηf′(x(1))x(3)=x(2)−ηf′(x(2))

In general, the recursive rule is:

x(t)=x(t−1)−ηf′(x(t−1))

Why doesn't this overshoot forever? As the solution gets closer to the local minimum, the slope f′(x(t−1)) approaches zero (since at a minimum, the derivative is exactly 0). This means the update term ηf′(x(t−1)) shrinks towards zero as well, so consecutive solutions barely change — this naturally slows down and eventually halts the algorithm near the optimum.

This gives us a natural stopping criterion: stop iterating when the change between x(t) and x(t−1) becomes negligible, or when the gradient magnitude falls below a small threshold (e.g., 10−6).

Gradient Descent in n Dimensions

Everything above was derived for a scalar function f:R→R. Extending this to an n-dimensional function f:Rn→R requires only one conceptual change: replace the scalar derivative with the gradient vector.

∇f=[∂x1​∂f​∂x2​∂f​⋯∂xn​∂f​]⊤

The update rule becomes:

x(t)=x(t−1)−η∇f(x(t−1))

Directional derivative: The rate of change of f in an arbitrary direction v at point x is defined as:

Dv​f(x)=v⊤∇f(x)=cosθ

where θ is the angle between the direction v and the gradient ∇f(x) (assuming both are unit vectors).

This directional derivative is maximized when θ=0°, i.e., when v points in exactly the same direction as ∇f(x):

vmax​v⊤∇f(x)=1whenv=∇f(x)

This is the formal justification for why the gradient direction gives the steepest ascent, and consequently, why the negative gradient direction gives the steepest descent — moving there decreases the function value the fastest among all possible directions, not just left/right as in the 1D case.

Note for Review: In 1D there are only two directions to move (left or right), but in n dimensions there are infinitely many directions. The gradient tells you which single direction, out of infinitely many, decreases the function the fastest — this is the real power of generalizing from slopes to gradients.

The Gradient Descent Algorithm

Putting it all together, the algorithm is remarkably short:

Algorithm: Gradient Descent

  1. Initialize x(0) and step size α.
  2. t←0
  3. while not converged do
  4. x(t+1)←x(t)−α∇f(xt)
  5. t←t+1
  6. end while

Here α (also written η) is the learning rate, and convergence is typically checked either via the magnitude of the gradient or the difference between consecutive solutions.

Geometrically, if you view the contour plot of a bowl-shaped function from above, gradient descent traces a path of steps, each perpendicular to the local contour line, spiraling inward toward the global minimum.

This algorithm (or one of its many variants) underlies the training of virtually all modern neural networks.

Worked Example: The Effect of Learning Rate

To build intuition, consider the simple one-dimensional function:

f(x)=x2−2x,f′(x)=2x−2

Solving f′(x)=0 classically gives x=1 as the optimal (global minimum) solution. We now verify that gradient descent, starting from an arbitrary initial guess, actually converges to this point — and that the choice of learning rate α dramatically changes how (and whether) it converges.

Case 1: Small learning rate (α=0.1)

Starting at x(0)=3:

  • f(x(0))=3, and f′(x(0))=2(3)−2=4

Iteration 1: x(1)=x(0)−αf′(x(0))=3−0.1×4=3−0.4=2.6

Iteration 2: (f′(2.6)=2×2.6−2=3.2) x(2)=2.6−0.1×3.2=2.6−0.32=2.28

Iteration 3: (f′(2.28)=2×2.28−2=2.56) $ x^{(3)} = 2.28 - 0.1 \times 2.56 = 2.28 - 0.256 = 2.024

$

After 3 iterations we've only gotten roughly halfway to x∗=1. Notice the gradient magnitude is shrinking at each step (4→3.2→2.56), which is exactly why the step sizes shrink and convergence slows near the optimum. It would take several more iterations (roughly 7–8 more) to get very close to x∗=1.

Case 2: Well-tuned learning rate (α=0.5)

Starting again at x(0)=3:

Iteration 1: x(1)=3−0.5×4=3−2=1

Iteration 2: (f′(1)=2(1)−2=0) x(2)=1−0.5×0=1

Here, gradient descent reaches the exact optimal solution x∗=1 in a single iteration, and then stays there forever since the gradient at the optimum is zero.

Case 3: Learning rate too high (α=1)

Starting at x(0)=3:

Iteration 1: x(1)=3−1×4=−1

The algorithm has now overshot the optimum entirely, landing on the opposite side of the curve.

Iteration 2: (f′(−1)=2(−1)−2=−4) x(2)=−1−1×(−4)=−1+4=3

We've jumped straight back to the starting point! If you continue this process, the algorithm will keep oscillating between x=3 and x=−1 forever, never settling at the true minimum x∗=1.

Takeaways on Learning Rate

Learning Rate Behavior Outcome
Too small (α=0.1) Converges, but very slowly Needs many iterations
Well-tuned (α=0.5) Converges quickly (here, in 1 step) Ideal
Too high (α=1) Oscillates between two points Never converges
Even higher (α=2) Diverges — function value increases without bound Completely fails

Pro-Tip: This is one of the most commonly tested exam concepts. Remember: a too-small learning rate wastes computation (slow convergence), while a too-large one can cause oscillation or outright divergence. For real neural networks with millions of parameters, tuning the learning rate is one of the most critical and difficult parts of training — this single-variable example already shows how delicate the balance is.

Logistic Regression Recap

Having built intuition for gradient descent on a simple quadratic, we now apply it to a problem that cannot be solved with a closed-form solution: logistic regression.

Consider the problem of classifying papayas into two classes: "Tasty" and "Non-Tasty", based on features such as color and smoothness. Given a training dataset:

{(x1​,y1​),(x2​,y2​),…,(xm​,ym​)}

where xi​ represents the i-th papaya's features and yi​ its taste label, we use binary labels:

  • yi​=0 for a non-tasty papaya
  • yi​=1 for a tasty papaya

We assume the two classes are linearly separable — meaning a straight line (or hyperplane, in higher dimensions) can perfectly divide tasty from non-tasty papayas based on their features.

The goal is to find a linear classifier:

The Sigmoid Function

Since we want our classifier's output to represent a probability (a value strictly between 0 and 1), a raw linear function θ⊤x won't do — it's unbounded. Instead, we pass the linear score through the sigmoid function:

hθ​(x)=g(θ⊤x)=1+e−θ⊤x1​

As z→−∞, g(z)→0; as z→+∞, g(z)→1. This gives us exactly the [0, 1]-bounded output we need — if hθ​(x)<0.5 we predict non-tasty, and if hθ​(x)≥0.5 we predict tasty.

Deriving the sigmoid's gradient (needed later for gradient descent):

g(z)=1+e−z1​g′(z)=dzdg(z)​=(1+e−z)21​e−z=1+e−z1​⋅1+e−ze−z​=1+e−z1​(1−1+e−z1​)g′(z)=g(z)(1−g(z))

This elegant closed-form result — the derivative of the sigmoid is simply the sigmoid times one minus itself — is what makes logistic regression's gradient computations tractable.

Note for Review: This "g(z)(1−g(z))" trick is one of the most reused identities in deep learning — it appears in backpropagation for any network using a sigmoid activation. Memorize the derivation, not just the result.

Maximum Likelihood Estimation for Logistic Regression

We treat hθ​(xi​) directly as a probability:

P(yi​=1∣xi​)=hθ​(xi​),P(yi​=0∣xi​)=1−hθ​(xi​)

These two cases can be elegantly combined into a single expression (a standard trick: whichever term doesn't apply gets raised to the power 0, vanishing):

P(yi​∣xi​)=(hθ​(xi​))yi​(1−hθ​(xi​))1−yi​

Assuming the data points are independent and identically distributed, the joint likelihood over the whole dataset is the product of individual probabilities:

L(θ)=p(y1​,…,ym​∣x1​,…,xm​)=i=1∏m​p(yi​∣xi​)=i=1∏m​(hθ​(xi​))yi​(1−hθ​(xi​))1−yi​

Rather than maximizing this product directly (which is numerically awkward), we take the log-likelihood. Since the logarithm is a monotonically increasing function, it doesn't shift the location of the maximum — it only reshapes the function, which conveniently turns the product into a sum:

ℓ(θ)=log(L(θ))=i=1∑m​yi​log(hθ​(xi​))+(1−yi​)log(1−hθ​(xi​))

This expression is exactly the (negative of the) binary cross-entropy loss commonly seen in classification tasks. Our goal is now to maximize ℓ(θ) with respect to θ.

Since ℓ(θ) involves the sigmoid function nested inside logarithms, it is a highly non-linear function of θ — unlike linear regression's quadratic objective, there is no closed-form solution. This is precisely why we need gradient-based optimization here.

Deriving the Gradient of the Log-Likelihood

To apply gradient ascent, we need ∂θj​∂ℓ(θ)​ for each parameter θj​:

∂θj​∂ℓ(θ)​=i=1∑m​yi​hθ​(xi​)1​∂θj​∂hθ​(xi​)​−(1−yi​)1−hθ​(xi​)1​∂θj​∂hθ​(xi​)​=i=1∑m​(yi​hθ​(xi​)1​−(1−yi​)1−hθ​(xi​)1​)∂θj​∂hθ​(xi​)​

Using the sigmoid derivative identity g′(z)=g(z)(1−g(z)) derived earlier:

=i=1∑m​hθ​(xi​)(1−hθ​(xi​))(yi​−hθ​(xi​))​g(θ⊤xi​)(1−g(θ⊤xi​))∂θj​∂θ⊤xi​​

The hθ​(xi​)(1−hθ​(xi​)) terms cancel beautifully with the sigmoid derivative, leaving a remarkably simple final result:

∂θj​∂ℓ(θ)​=i=1∑m​(yi​−hθ​(xi​))xij​

This clean form — "(actual minus predicted) times feature value, summed over all data points" — is what makes logistic regression's gradient so practical to compute despite the non-linearity of the original loss function.

Gradient Ascent Algorithm for Logistic Regression

Since we are maximizing the log-likelihood (not minimizing), the update uses a plus sign instead of the minus sign we saw in standard gradient descent — this variant is technically called gradient ascent:

Algorithm: Gradient Descent (Ascent) for Logistic Regression

  1. Input: Training dataset {(x1​,y1​),(x2​,y2​),…,(xm​,ym​)}
  2. Initialize θ(0) and step size (learning rate) α.
  3. t←0
  4. while not converged do
  5. for j∈{0,1,2,…,d} do
  6. θj(t+1)​←θj(t)​+α∑i=1m​(yi​−hθ​(xi​))xij​
  7. end for
  8. t←t+1
  9. end while
  10. Output: Optimal classifier hθ∗​

Note for Review: You can just as easily frame this as a minimization problem by minimizing the negative log-likelihood — flip the sign, and the update rule becomes a subtraction, matching the standard gradient descent form: θj(t+1)​←θj(t)​−α∑i​(hθ​(xi​)−yi​)xij​. Both formulations are equivalent and both appear frequently in textbooks — don't let the sign flip confuse you in an exam.

At convergence, the resulting θ∗ defines the optimal logistic regression classifier — unlike linear regression, this required an iterative procedure since no closed-form solution exists.

The Scalability Problem

Looking closely at the gradient update rule:

θj(t+1)​←θj(t)​+αi=1∑m​(yi​−hθ​(xi​))xij​

notice the summation over all m training points, computed for every parameter θj​, on every single iteration.

This is fine for small datasets, but consider a modern large language model with training sets containing millions of data points and millions (or billions) of parameters, trained over millions of iterations. Performing a full summation over the entire dataset at every step becomes computationally infeasible.

This is a fundamental drawback of standard (a.k.a. "batch") gradient descent, and it directly motivates the need for more scalable variants of the algorithm — such as Stochastic Gradient Descent (SGD) and mini-batch gradient descent — which will be covered in the next module.
